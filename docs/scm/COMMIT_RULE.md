# PASO AI 커밋 규칙 (Commit Rule)

PASO AI 프로젝트의 모든 커밋 메시지는 일관된 히스토리 추적과 버전 관리를 위해 아래 규칙을 준수합니다.

---

## 1. 커밋 메시지 기본 포맷

```text
<type> : <간결한 변경 요약> (v<버전>)

- 상세 변경 사항 1
- 상세 변경 사항 2
```

### 예시
* `docs : 형상관리(SCM) 커밋 및 PR 규칙 문서 작성 (v0.0.0.1)`
* `feat : 특허 청구항 트리 구조 파서 기능 추가 (v0.0.0.2)`
* `fix : KIPRIS API 응답 타임아웃 예외 처리 수정 (v0.0.0.3)`

---

## 2. 커밋 타입 (`<type>`) 정의

콜론(`:`) 앞뒤로 공백을 한 칸씩 두는 형식(`type : 제목`)을 기본으로 사용합니다.

| 타입 | 설명 |
| :--- | :--- |
| **`feat`** | 새로운 기능 추가 (백엔드 API, 프론트엔드 UI, AI 파이프라인 등) |
| **`fix`** | 버그 및 오류 수정 |
| **`docs`** | 문서 추가 및 수정 (`README.md`, `docs/` 하위 문서 등) |
| **`refactor`** | 기능 변경 없는 코드 구조 개선 및 리팩토링 |
| **`style`** | 코드 포맷팅, 세미콜론 누락, 주석 정리 등 (로직 변경 없음) |
| **`test`** | 단위 테스트 및 통합 테스트 코드 추가/수정 |
| **`chore`** | 빌드 설정, 패키지 매니저, 디렉토리 구조, 버전(`VERSION`) 관리 등 |

---

## 3. 작성 원칙

1. **제목(Subject)은 한글 기준 50자 이내**로 명확하고 간결하게 작성합니다.
2. **명령조/명사형 종결**을 사용합니다. (예: `~했음` 대신 `~추가`, `~수정`, `~구현`)
3. **매 수정(커밋/PR 단위)마다 4자리 버전(`0.0.0.x`)을 갱신**하며, 루트의 `VERSION` 파일과 동기화합니다.
4. 하나의 커밋에는 하나의 논리적 작업만 포함되도록 작게 나누어 커밋합니다.
